# Bug清剿小队（Bug Purge Squad）· trontank

> 一个零依赖、单文件的俯视角双摇杆射击小游戏。复刻自 WorkBuddy 社区的原创作品，并在其基础上增加了 **WebHID 手柄支持**、**P1/P2 手柄分配** 与 **拾取磁吸** 等改动。

本文档面向 agent / 协作者，重点说明项目结构、设计思路与**所有可调参数**，便于快速理解与二次开发。

---

## 1. 项目简介

- **玩法**：俯视角（top-down）双摇杆射击。玩家清除不断涌出的「异常数据体（bug）」，守护中央数据核心。
- **模式**：单人（solo）/ 双人同屏（duo，同一键盘分控）。
- **核心循环**：清波 → 整备（选增益卡）→ 下一波；三档难度。
- **内容**：4 种武器（手枪/冲锋枪/散射霰弹/穿透光束）、3 种补给（修复药剂/护盾/超频芯片）、墙面武器架、地面宝箱、小地图、镜头跟随、倒地救援、热修复连携、本地最高分、全屏。
- **美术与音效**：全部由代码程序生成（Canvas 绘制 + WebAudio 合成），**无任何外部素材**。

## 2. 运行与部署（重要）

- **唯一文件**：`index.html`（约 21 万字节，自包含：1 个 `<style>` + 1 个 `<script>`，无 CDN、无外链、无构建步骤）。
- **本地预览**：用 WorkBuddy 内置预览（走 `localhost`，可直接用手柄）或浏览器打开。
- **外部浏览器 / 部署**：
  - 纯静态站点即可，**无需后端、数据库或运行时**。
  - ⚠️ **必须 HTTPS（或 `localhost`）访问**。手柄的 **WebHID API 只在安全上下文下可用**；用 `file://` 双击打开或纯 `http://域名` 访问时，`navigator.hid` 会被浏览器禁用，页面会提示改用 `http://localhost` 或 https。
  - 宝塔部署：新建静态站点 → 上传 `index.html` → 开启 SSL（Let's Encrypt）→ 访问 `https://你的域名/`。
  - **当前线上部署**：`67.215.237.94` → `/www/wwwroot/tron.zhaoyouhan.com/`，访问 `https://tron.zhaoyouhan.com`。**改完本地 `index.html` 必须重新上传覆盖才会生效。**

## 3. 架构概览

整个游戏是单文件，按「常量 → 数据 → 工具 → 系统 → 主循环」组织，关键锚点（行号随改动可能偏移，以搜索为准）：

| 区块 | 作用 | 关键标识 |
|---|---|---|
| `var CFG = {...}` | 全局可调平衡参数（玩家/拾取） | `CFG` |
| `DIFFS` | 难度倍率 | `DIFFS`, `difficulty` |
| `WEAPONS` / `SUPPLIES` | 武器与补给的数据驱动定义 | `WEAPONS`, `SUPPLIES` |
| `TERRAIN_SETS` | 每波的地形/武器架/宝箱布局 | `TERRAIN_SETS` |
| 敌人定义 | bit/block/tri/hex 四类异常体 | `enemyTypes` |
| `makePlayer` | 玩家对象初始化（半径取自 `CFG.playerR`） | `makePlayer` |
| `updatePickups` | 掉落物磁吸 + 拾取判定 | `updatePickups` |
| `pollGamepads` / `gpRead` / `hidBuildPseudo` | 手柄输入（标准 API + WebHID） | 见第 6 节 |
| 主循环 | `loop()` → `update(dt)` → 渲染 | `function update` |

持久化使用 `store`（localStorage 封装），键名带版本后缀（如 `bqs.diff.v1`、`bqs.binds.v1`、`bqs.gpTarget.v1`）。

## 4. 设计思路

1. **单文件、零依赖**：便于直接发布为静态页、离线运行、无构建链路。任何新功能都应尽量保持「不改外部依赖」。
2. **数据驱动平衡**：武器/补给/难度/地形都是纯数据对象，改数值即可调玩法，不必动逻辑。
3. **流程优先于精准**：拾取改为「磁吸 + 放大判定半径」，玩家路过装备即自动入袋，避免必须精确走到道具上影响流畅度（见 `CFG.pickupRadius` / `pickupAttractR` / `pickupAttractSpeed`）。
4. **手柄兼容分层**：
   - 标准手柄（Xbox/PS）走浏览器原生 `Gamepad API`（`gpRead` 解析标准按钮索引）。
   - **Switch Pro Controller / Joy-Con 在 macOS 上不被 Gamepad API 暴露**（它是 BLE HID，系统手柄层跳过），因此额外实现 **WebHID 直连**，直接解析其 `0x30` 输入报告（`hidBuildPseudo`）。两条路径最终都喂给同一套 `padHeld` 输入状态，逻辑统一。
5. **可配置的手柄归属**：双人模式下可在「按键设置」里指定第 1 只手柄归 P1、P2 还是双柄各一（`gamepadTarget`）。

## 5. 操作方式

### 键盘（默认，可在「按键设置」中修改）
- **1P**：`WASD` 移动，`J` 射击，`Q` 切枪，`E` 投弹；方向键也可移动。
- **2P**：方向键移动，`右Shift` 射击，`/` 切枪，`.` 投弹。
- **通用**：`P` / `Esc` 暂停；`R` 结束本局并出结算卡；`F` 全屏；`1-3` 选卡。

### 5.x 结算与分享卡
- **一局的结束 = 一张修复报告**：阵亡结算、暂停面板点「结束本局」、局中直接按 `R`，三条路径都走同一个 `endGame(fromPause)`，弹出可截图的分享卡（`#resultPanel`，含「保存分享卡」导出 PNG）。暂停面板没有单独的「返回开始页」——弃局统一先出卡，卡上再选「再来一局」或「返回开始页」，避免两个按钮指向同一处。
- 中途结算（`fromPause === true`）额外给一个 **「继续本局」**（`#btnContinue`），回到结算前的状态（`settleBack`，整备阶段会恢复选卡面板），避免误点丢进度；阵亡结算没有这个按钮。
- 结算页按 `R` = 再来一局（`startGame`），不会重复结算。
- 中途结算同样写入本地最高分（`getBest` 取最大值，可安全重复写）。

### 手柄（需 Chrome/Edge + HTTPS/localhost）
> Switch 手柄的键帽字母与 Xbox 的物理位置差 90°，两者不可兼得，因此做成**可切换布局**（默认 `xbox`）。

| 说明 | Xbox 布局（默认，按**位置**） | Switch 原生（按**键帽字母**） |
|---|---|---|
| 射击 | **下**（= Pro 键帽 B） | **A** |
| 切枪 | **左**（= Pro 键帽 Y） | **X** |
| 投弹 | **上**（= Pro 键帽 X） | **Y** |

- 任何布局下 **Pro 键帽 A 与 ZR 都能射击**（兜底，避免切换后没键开火）。
- 菜单：当前布局的射击键=单人，投弹键=双人，`+`=操作说明，`-`=按键设置；战斗中 `+`=暂停。
- 切换入口：「按键设置 → 手柄面键布局」，持久化于 `bqs.padLayout.v1`。

### 5.4 按键设置弹窗布局（避免垂直滚动条）
- 面板宽度 `min(100%, 58em)`（原 40em），内边距 `1.6em 1.8em`；高度靠**横向**省出来，而非靠滚动。
- 三处双列：每位玩家的 7 个动作在块内分 2 列（`.keys-rows`，4+3）；两个手柄配置块并排（`.gp-blocks`）；两条静态说明并排（`.keys-notes`）。
- `#keysNote`（id 选择器）是**状态提示条**，JS 会重置其 className，故样式必须挂在 id 上，不能靠额外 class。
- 窄屏（`max-width:760px`）上述四项自动退回单列堆叠。

## 6. 开发可调参数

> 改完数值即生效，无需构建。所有「平衡类」参数都集中在少数几个对象里，优先在这里调，避免散落硬编码。

### 6.1 全局平衡 `var CFG = {...}` （玩家 + 拾取）
| 参数 | 默认值 | 含义 |
|---|---|---|
| `playerR` | 15 | 玩家碰撞/判定半径 |
| `playerHp` | 100 | 玩家生命上限 |
| `playerSpeed` | 215 | 移动速度（px/s） |
| `fireInterval` | 0.30 | 基础射击间隔（秒） |
| `damage` | 10 | 基础单发伤害 |
| `bulletSpeed` | 680 | 子弹速度（px/s） |
| `bulletR` | 4 | 子弹半径 |
| `hitInv` | 1.2 | 受击无敌帧（秒），被围时给脱身机会 |
| `reviveRatio` | 0.85 | 倒地救援后回血比例 |
| `pickupRadius` | 22 | 拾取触发半径（与玩家半径相加）。原 9（≈需走到 24px），现 22（≈37px，路过即捡） |
| `pickupAttractR` | 72 | 磁吸半径（px）：玩家进入此范围，掉落物主动飞向角色 |
| `pickupAttractSpeed` | 280 | 磁吸最大速度（px/s），越近吸得越快 |
| `aimAssistEnabled` | true | 瞄准辅助（小角度自动修正）总开关，一键回退 |
| `aimAssistAngle` | 10 | 默认最大修正角（度）：玩家射线与敌人偏差≤此值才修正，超出不修正（保留瞄准手感） |
| `aimAssistRange` | 360 | 只辅助此距离内的敌人（px）；0 = 不限距离 |
| `moveReleaseGrace` | 0.08 | 斜向释放保护（秒）：斜向→仅剩单轴时**只保护朝向、不冻结移动**，位移照常响应（零迟滞），朝向在该窗口内保持不变以免松手时差把 45° 掰平；0 = 关闭 |
| `moveReleaseFreeze` | false | 回退开关：保护期内连移动一起冻结（旧行为）。开着能消掉松手瞬态约 3~4px 的位移，但代价是每次斜向转正向迟滞约 `moveReleaseGrace`，手感发黏 |
| `hidInvertY` | true | WebHID 摇杆竖轴取反（原始值向上推=变大，需转成向上=负）。仅影响 WebHID 通路；若接上后上下仍颠倒，在 true/false 间切换 |

> **每武器差异化**：`WEAPONS` 里可用 `aimAssist` 字段单独覆盖上述角度——例如 `beam` 设 16（单发高伤、容错低，给更大修正），`scatter` 设 0（自身 26° 扇形已覆盖错位，不需额外修正），未设则沿用全局 10°。

> **斜向释放保护与手柄兼容**：该逻辑施加在「键盘 + 手柄合并后的最终方向向量」上（`updatePlayer` 内、`p.moving` 结算之前），因此键盘松开双键的时差、以及**手柄摇杆从斜向回中时先跨过单轴**这两种瞬态都能被消除，双方都可实现「停住并保持 45° 瞄准」。
>
> ⚠ **只保护朝向、不冻结移动**：保护期内位移照常跟随输入（转向零迟滞），仅朝向保持不变。实测斜向转正向的位移迟滞由「冻结位移」方案的 ~100ms 降为 0（首帧即移动），代价是松手瞬态有约 3.6px 微漂；若更在意这点位移，把 `moveReleaseFreeze` 设为 `true` 退回旧行为。
> 保护期内：完全松手→停止且保留斜向瞄准；按回第二个方向→立即恢复；超时仍单轴→朝向更新为该方向（位移全程不受影响）。

### 6.7 世界与敌人
- **视口与世界都是动态的**（`setupCanvas()` 里按 `#stage` 的 CSS 尺寸计算，不再固定 960×540）：
  - `DESIGN_DENSITY = 1100/960 ≈ 1.146` —— 每逻辑单位对应的 CSS 像素。**保持恒定**是关键：角色/UI 在屏幕上的相对大小不变，且 `canvas 物理像素 = #stage CSS 尺寸 × DPR`，即 **1:1 原生渲染，放大不糊**。
  - `WORLD_MUL = 1.8` —— 世界 = 视口 × 该倍数（两方向同比）。同比的意义是让「屏幕内敌人密度」 `V/A = 1/1.8² ≈ 0.3086` **恒定**，换屏幕不会改变难度。
  - `MAX_PHYSICAL_PIXELS = 5.8e6` —— 填充率预算，仅超大屏/4K 全屏才轻微降采样保护帧率（常规笔记本全程 1:1）。
  - `BASE_WW/BASE_WH = 1728/972` —— 地形坐标的设计基准（**不是**当前世界尺寸）。
- 敌人类型（`enemyTypes`）：`bit`(hp10,spd92,r12,score100) / `block`(hp22,spd62,r13,score150) / `tri`(hp16,spd112,r14,score170) / `hex`(hp32,spd56,r17,score230)。
- 地形分两层，合成 **10 种**地形池：
  - `TERRAIN_SETS`：5 套手工设计关卡（外加 `[0]` 开阔场给精英波），纯数据可增删。
  - `PROC_GENS`：5 种程序化生成器 —— `ring` 环柱裂隙 / `zigzag` 锯齿通道 / `diagonal` 斜断回廊 / `maze` 随机格栅 / `scatter` 柱群废墟。用 `mulberry32(seed)` 确定性生成：**同一波内重建（含窗口缩放）结果一致**。
  - `jaggedObstacles()`：**所有**地图（含手工关卡）实例化前都会过一遍「碎墙」——把长度 ≥110 的轴对齐墙拆成 2~8 段、沿厚度方向随机错位（振幅 10~30px），轮廓从方正的矩形墙变成错台锯齿。拆段沿墙方向首尾各多 2px 重叠、只平移不缩放，**物理上仍严丝合缝**，不会出现能穿过或打穿的缝。改这里只影响观感，别动重叠量。
  - `TERRAIN_POOL` = 程序化 5 与固定 5 **交错编织**（环柱裂隙→双柱走廊→锯齿通道→十字隔墙…），固定顺序时也不会连吃两关同一风格。
  - 顺序规则：**只有「挑战」难度** `shuffleTerrainPlan()` 才洗牌，每局闯关顺序都不同；休闲/标准固定走池子顺序。种子也随之分叉：挑战用 `runSeed`（每局变），另两档用固定基值（同一关每局完全一致）。波次每 2 波一个槽位，10 槽 ≈ 20 波走完才重复。`CFG.terrainShuffle = false` 可整体退回旧的固定轮换；精英波（5 的倍数）始终是开阔场，不占槽位。
  - 程序化地形统一过 `decorateProcTerrain()`：按「障碍形状 vs 出生圈的真实重叠」剔除压在出生点的障碍 —— **不要用中心点距离判断**，长横墙中心离得远但墙身不挡人，用中心判会把整条墙误删；剔除后在空地随机放 2 宝箱 + 2 武器架。
  - 调试：页面带 `?debug` 打开会挂 `window.__bqs`，可用 `startWave(n)` 跳波、`current()` 读当前地形、`reroll()` 重掷地形序列（内部临时按挑战规则洗牌，低难度也能看效果）。生产游玩不受影响。
  ⚠️ **所有坐标是 BASE_WW×BASE_WH（1728×972）下的绝对值**，`buildObstacles()` 会按 `kx = WW/BASE_WW`、`ky = WH/BASE_WH` 缩放后再实例化（圆形半径用 `min(kx,ky)` 防变形）。**新增地形/生成器一律按 1728×972 写，不要按当前世界尺寸写。**
  ⚠️ 双人出生点同理，已改为按比例（`WW × 480/1728`、`WW × 1248/1728`），不要改回绝对坐标。

### 6.7.1 舞台尺寸（CSS）
- 桌面（≥761px）：`width: min(98vw, 96vh*2.2)`、`height: min(96vh, 98vw/1.2)`，去掉 16:9 固定比例 → 屏幕利用率约 **94%**（改造前受 1100px 上限限制仅约 52%）。宽高比被夹在 1.2–2.2，避免超宽屏把战场拉成细带。
- 窄屏（<761px）：维持 `aspect-ratio:16/9` 原逻辑，避免手机竖屏视野被拉成长条。
- 全屏：`object-fit:fill`（逻辑分辨率已跟随比例，无需 contain，否则会留细黑边）；进出全屏监听 `fullscreenchange` 重算（此时窗口尺寸不变、变的是 `#stage`）。
- 世界尺寸变化后由 `clampEntitiesToWorld()` 把实体拉回新边界；地形不立即重建，下一波 `buildObstacles` 时自动适配。

### 6.8 手柄配置
- **WebHID 过滤设备**（`requestGamepad` 的 `filters`）：Switch `vendorId 0x057e` 的 `productId 0x2009`(Pro Controller) / `0x2006`(Joy-Con L) / `0x2007`(Joy-Con R)。要支持其他蓝牙手柄，在此加 filter 并在 `hidBuildPseudo` 里加对应报告解析。
- **面键索引**（`gpRead` 读取）：0=A、1=B、2=X、3=Y、7=ZR、8=Minus、9=Plus、12–15=十字键。
- **面键布局** `padLayout`：取值 `'xbox'`（默认，按物理位置）/`'switch'`（按键帽字母），索引表在 `PAD_LAYOUTS`。
  ⚠️ **两通路语义不同**：Gamepad API 的 `standard` mapping 是按 *Xbox 位置* 编号的，而 WebHID 的 `0x30` 报告我们按 *Pro 字母* 编号 —— **同一个索引在两条通路下可能对应不同的物理键**。这是「换个浏览器/换个通路手感就变了」的根因，改动前务必先看清走的哪条路。
- **手柄归属** `gamepadTarget`：取值 `'p1'` / `'p2'` / `'both'`（默认 `'both'`）；单人模式恒为 P1。配置存于 `bqs.gpTarget.v1`。
- **诊断开关**：URL 加 `?debug=hid`（如 `https://域名/?debug=hid`）可在左下角实时显示原始报文前 12 字节 + 解析后的双摇杆值，手柄异常时优先用它取证。

### 6.9 Switch `0x30` 报告解析口径（改这里前务必读）
`hidBuildPseudo` 依赖两个易错事实，**改错任意一个都会让手柄完全失控**：

1. **WebHID 的 `inputreport.data` 不含 reportId**（MDN 明确），所以报文索引是「去掉报告号」的编号：
   - `data[2]` = **face 组**：`0x01 Y`、`0x02 X`、`0x04 B`、`0x08 A`、`0x40 R`、`0x80 ZR`
   - `data[3]` = **Shared 组**：`0x01 Minus`、`0x02 Plus`、`0x10 Home`、`0x20 Capture`、`0x80 ChargingGrip`
   - `data[4]` = **左/方向组**：`0x01 下`、`0x02 上`、`0x04 右`、`0x08 左`
   - ⚠️ `data[3] & 0x80` 是 **Charging Grip 状态位，绝不能当 ZR 读**——否则会表现为「一直自动射击」。
2. **12 位摇杆重组公式**（左右摇杆分别占 3 字节：`5-7` / `8-10`）：
   - 横向 `X = byte0 | ((byte1 & 0x0F) << 8)`
   - 竖向 `Y = ((byte1 & 0xF0) >> 4) | (byte2 << 4)` ← ⚠️ 竖向是 `<< 4` 而不是 `<< 8`
   - 写成 `(高半字节 << 8) | byte2` 时，中心值会解码成 128 → 归一化后恒为 **−1（一直向上冲）**。中心 ~2048、满偏 ~1280，轻微中心偏移由 `gpRead` 的 0.35 死区吸收，无需逐台校准。
3. **竖轴必须取反**（`CFG.hidInvertY`，默认 `true`）：
   - 原始口径是「**向上推 = raw 变大**」，而游戏与 Gamepad API 用屏幕坐标（**向上 = 负值**），故 `ly / ry` 需乘 −1。
   - 不取反的表现：**上下颠倒**（摇杆推上角色往下走）。因为标准 Gamepad API 由系统/浏览器已标准化，所以 **只有 WebHID 通路（Chrome）会暴露此问题，Safari 反而正常** —— 这个「Chrome 反、Safari 正常」的组合是判断此 bug 的特征信号。
   - 只作用于摇杆轴；十字键位（`0x02 上` / `0x01 下`）本身正确，不受影响。

## 7. 已知限制与注意事项

- **WebHID 仅 Chrome / Edge 支持**，Safari 无效（按钮会提示「此浏览器不支持」）。
- **务必 HTTPS/localhost**：否则手柄完全不可用（`file://` 与纯 http 都会被禁）。
- Switch 的 **Home 键是系统保留键**，网页层无法拦截（属正常，不影响游戏）。
- **Safari 用手柄受限（但与 HTTPS 无关）**：Safari 不支持 WebHID，只能走 Gamepad API；而后者能否枚举到 Pro Controller 取决于两件事 ——
  1. **macOS 版本**：需 Ventura(13)+ 才原生支持该手柄（旧版 Darwin 的 HID 手柄服务覆盖不到它）；
  2. **必须按手柄键激活**：所有浏览器都要求这个用户手势才会暴露设备。
  ⚠️ 最常见的失效原因是 **WebHID 独占 HID 设备**：只要刚用 Chrome 点过「连接手柄」，macOS 就不再把手柄交给 Safari，`getGamepads()` 必然返回空。解决：**完全退出 Chrome** 后再用 Safari。
- **诊断开关**：`?debug=hid` = 原始报文 + 双摇杆解析；`?debug=pad` = 枚举实况（UA / secureContext / `navigator.hid` / `getGamepads()` 长度与每个槽位的 id·mapping·axes·buttons / `gamepadconnected` 触发次数）。手柄异常时**先用它取证再改**。
- `gamepadconnected` 监听在 `<script>` **第一行**就注册（远早于游戏脚本尾部），避免线上加载慢时用户手势早于监听器注册、事件被丢弃。
- 手柄键位用的是标准索引假设；若实测某键不对，改 `gpRead` / `hidBuildPseudo` 里对应的位/索引即可（一行级改动）。先用 `?debug=hid` 取证再改。
